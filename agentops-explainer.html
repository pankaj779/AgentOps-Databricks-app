Use Tools: Query databases, call APIs, read files

Make Decisions: Choose which action to take next

Remember: Keep track of conversation and state

Example: A "Sales Agent" on Databricks might receive a customer query, look up the customer in a database, check their purchase history, generate a personalized recommendation, and update the CRM - all automatically.

Deep Dive: What is Lakebase?

🏠

The Simple Analogy

Imagine you have a library (Databricks Lakehouse) where you store millions of books (data) for research (analytics). This library is great for reading and analysis, but it's slow - if you need to quickly check a book in and out, it takes time.

Now imagine you also need a front desk where transactions happen fast - someone returns a book, someone borrows one, you update the inventory instantly.

Previously, you needed a separate building (external database like PostgreSQL or MySQL) for this front desk work. And every night, you had to manually carry copies of the transaction records from the front desk to the library so analysts could study them.

Lakebase = a front desk BUILT INSIDE the library. No more separate building. No more manual copying. Everything is in one place.

The Technical Explanation

There are two types of databases in the world:

Type OLTP (Transactional) OLAP (Analytical)
What it does Fast reads/writes for applications Heavy analysis on large datasets
Speed Milliseconds (sub-10ms) Seconds to minutes
Example use User logs in, agent updates a record "Show me sales trends for last 3 years"
Traditional tool PostgreSQL, MySQL Databricks, Snowflake, BigQuery

The old problem: Companies needed BOTH. They ran PostgreSQL separately for their apps, and Databricks for analytics. They built complex ETL (Extract-Transform-Load) pipelines to copy data between them every few hours. This was:

Expensive: Two separate systems to maintain and pay for

Fragile: ETL pipelines break constantly

Stale: Analytics data was always hours behind

Ungoverned: Security rules didn't carry over between systems

Lakebase Solves This

Lakebase is a fully managed PostgreSQL database that lives INSIDE Databricks.

It means you can now build apps (with fast read/write) AND do heavy analytics on the same platform. No ETL pipelines needed. Same security rules everywhere. Data is always fresh.

It's compatible with standard PostgreSQL, so any tool that works with Postgres (pgAdmin, SQLAlchemy, Django, etc.) works with Lakebase too.

Key Features of Lakebase

SERVERLESS

Scales up/down automatically. Can even scale to zero when nobody is using it - you only pay for what you use.

GIT-LIKE BRANCHING

Create a copy of your entire database in seconds for testing. Like creating a Git branch, but for a database.

UNIFIED GOVERNANCE

Uses Unity Catalog, so the same security rules apply to both your app data and analytics data.

AI READY

Supports pgvector for AI embeddings and PostGIS for location data out of the box.

How We Use Lakebase in Our Accelerator

Our AgentOps Dashboard is a web application. Like any web app, it needs a database to store:

  • Dashboard configuration (which agents to monitor, alert thresholds)
  • User preferences and saved views
  • Alert rules and notification history
  • Cached metrics for fast dashboard loading

Instead of using an external PostgreSQL, we use Lakebase - keeping everything inside Databricks. This is intentional because it showcases Lakebase as a real-world app backend.

Deep Dive: What are Inference Tables?

📹

The Simple Analogy

Imagine every AI agent in your company is an employee. Inference Tables are like security cameras that automatically record every conversation that employee has.

Every time someone asks the AI agent a question, the question (input), the answer (output), how long it took, and how many "words" (tokens) it used are all automatically saved to a table.

You don't have to write any code to enable this - just flip a switch, and Databricks starts recording everything.

What is AI Gateway?

AI Gateway is the "front door" for all AI model calls. Instead of each agent calling OpenAI/Anthropic/Llama directly, they go through the AI Gateway. This gateway:

  • Controls who can access which AI models (rate limiting, access control)
  • Routes requests to the right model
  • Automatically logs everything to Inference Tables

How We Use Inference Tables in Our Accelerator

Inference Tables are our primary data source. They already contain all the raw data about every agent call. Our dashboard simply reads this data and visualizes it - showing health metrics, costs, error rates, and performance trends. We don't need to build any logging system; it already exists.

Deep Dive: MLflow Tracing & Agent Evaluation

🔬

The Simple Analogy

Inference Tables tell you WHAT happened (this agent answered this question at this time).

MLflow Tracing tells you HOW and WHY it happened (the agent first searched the database, then read 3 documents, then thought about which one was relevant, then formulated the answer).

If Inference Tables are security cameras showing people entering and leaving a room, MLflow Tracing is an X-ray showing exactly what happened inside that room, step by step.

What MLflow Tracing Records

When an agent processes a request, it goes through multiple steps. MLflow Tracing records each step:

Step 1: Receive Input

User asks: "What were our top sales last quarter?"

Step 2: Tool Call - Database Query

Agent calls: query_sales_db(quarter='Q4', sort='desc', limit=10)

Step 3: Retrieval

Agent retrieves 10 rows of sales data from the database

Step 4: LLM Reasoning

Agent sends data to AI model: "Summarize these sales results..."

Step 5: Output

Agent responds: "The top 3 products by revenue were..."

Each step records: input, output, duration, tokens used, and any errors. This is invaluable for debugging - if the agent gives a wrong answer, you can trace back to exactly which step went wrong.

What is Agent Evaluation?

Agent Evaluation is the "grading system" for AI agents. It uses another AI model (called an "LLM Judge") to automatically grade the quality of agent responses:

GROUNDEDNESS

Is the answer based on actual data, or did the agent make things up? (detecting hallucinations)

RELEVANCE

Does the answer actually address what the user asked?

SAFETY

Does the answer contain harmful, biased, or inappropriate content?

CORRECTNESS

If we have the right answer, does the agent's answer match?

How We Use This in Our Accelerator

Our dashboard runs Agent Evaluation on a sample of production traffic (say 10% of all requests) and shows the quality scores as trends over time. If quality drops (e.g., groundedness score goes from 95% to 80%), the dashboard alerts the team immediately.

Deep Dive: What is Unity Catalog?

🔐

The Simple Analogy

Imagine a huge office building (Databricks). In this building, there are thousands of filing cabinets (tables), AI assistants (models), and applications (agents).

Unity Catalog is the building's security system + filing system combined. It knows:

  • WHERE everything is stored (like a directory)
  • WHO is allowed to access what (like key cards)
  • WHERE data came from and where it went (like a mail tracking system)
  • WHAT happened to data and when (like an audit trail / CCTV logs)

Without Unity Catalog, it's like having a building with no locks on doors and no visitor log.

Our Solution: The AgentOps Dashboard

A Databricks-native web application (deployed via Databricks Apps) that acts as a unified "control tower" for all AI agents running in production.

The 4 Panels

PANEL 1

Agent Health Monitor

Data source: Inference Tables

What it shows:

  • Real-time status of each agent (active, slow, erroring)
  • Requests per minute / hour / day
  • Average response time (latency)
  • Error rate (% of failed requests)
  • Alerts when an agent's error rate spikes above threshold

Value: Teams instantly know if something is broken, without writing SQL queries.

PANEL 2

Cost & Token Tracker

Data source: Inference Tables + System Tables (billing)

What it shows:

  • Token usage per agent, per day/week/month
  • Cost per agent (tokens x price per token)
  • Cost per feature/use case
  • "Token burn rate" - how fast an agent is consuming tokens
  • Projected monthly cost

Value: This is a MAJOR gap. Companies deploying agents often get surprised by bills. This panel prevents that.

PANEL 3

Quality & Safety Scorecard

Data source: MLflow Agent Evaluation (run on sampled production traffic)

What it shows:

  • Groundedness score over time (is the agent hallucinating?)
  • Relevance score (is it answering what was asked?)
  • Safety score (is it producing harmful content?)
  • Click any low-scoring response to see the full MLflow Trace (step-by-step reasoning)
  • Alerts when quality drops below threshold

Value: Catches hallucinations and quality regressions BEFORE users complain.

PANEL 4

Governance & Audit Trail

Data source: Unity Catalog (lineage + access logs)

What it shows:

  • Which data tables each agent accessed
  • Lineage map: data flow from source to agent response
  • Audit trail: who ran which agent, when, what was the input/output
  • Compliance flags for sensitive data access (PII, financial data)

Value: Essential for regulated industries (banking, healthcare). Proves agents are following the rules.

Data Flow Explained Simply

  1. Users interact with AI agents through apps, chatbots, or APIs
  2. AI Gateway routes these requests and automatically logs everything to Inference Tables
  3. MLflow Tracing captures the detailed step-by-step reasoning of each agent
  4. System Tables track the billing / token costs
  5. Unity Catalog governs everything and tracks data lineage
  6. Our AgentOps Dashboard reads ALL this existing data and presents it in 4 clean panels
  7. Lakebase stores the dashboard's own app data (configs, alerts, cached metrics)
